# SLSA Build Level — SZL Holdings · killinchu

**Current honest status: SLSA L1 + L2 (cosign-signed; signed provenance attestation independently verified via `cosign verify-attestation`).**

The published `ghcr.io/szl-holdings/killinchu` container image (tag `uds-v0.2.0`) is
built on a **hosted GitHub Actions builder** and ships a signed in-toto provenance
attestation generated by `actions/attest-build-provenance@v4` (Sigstore keyless:
Fulcio cert + Rekor transparency log). Every push to `main` rebuilds the image and
**re-attests the moved tag** in the same run (`.github/workflows/ghcr-build-push.yml`,
which also re-verifies its own attestation before the run may go green). The SLSA
Build L2 provenance attestation has been **independently verified** with
`cosign verify-attestation --type slsaprovenance` under strict per-organ identity
scoped to `https://github.com/szl-holdings/killinchu/` (keyless Fulcio + Rekor).
killinchu therefore meets **SLSA Build L1 + L2**.
L3 (hardened, isolated builder) is not claimed.

Most recently verified example — producing workflow run:
[29388018994](https://github.com/szl-holdings/killinchu/actions/runs/29388018994)
(2026-07-15); verified image digest at that time:
`sha256:82477051662e0d2dd5f5522acc03d2c8b4dc524feb25cadf712e3ff1d6e90eb3`
(verified 2026-07-15 with cosign v3.1.1). Because the tag is re-attested on every
`main` push, the current digest may be newer than this example; the verify commands
below always check the **current** tag.

## Verify (downstream)

> **Verifier version note (honest gotcha):** images attested after 2026-07 use the
> current Sigstore bundle format; **cosign ≥ 3.0 is required** to discover them.
> Older cosign 2.x reports `no matching attestations` for these images even though
> valid, Rekor-logged provenance exists (2.x only discovers legacy `.att` tag
> attachments, which pre-2026-07 digests still carry).

```bash
# L1: verify the cosign keyless signature on the published image.
cosign verify ghcr.io/szl-holdings/killinchu:uds-v0.2.0 \
  --certificate-identity-regexp='^https://github.com/szl-holdings/' \
  --certificate-oidc-issuer='https://token.actions.githubusercontent.com'

# L2: verify the signed SLSA provenance attestation (independently verified PASS).
# Returns a slsa.dev/provenance payload under strict per-organ identity scoped to
# killinchu (keyless Fulcio + Rekor).
cosign verify-attestation --type slsaprovenance \
  ghcr.io/szl-holdings/killinchu:uds-v0.2.0 \
  --certificate-identity-regexp='https://github.com/szl-holdings/killinchu/' \
  --certificate-oidc-issuer='https://token.actions.githubusercontent.com'
```

Source-release (tarball) provenance is **pending, not claimed**: the
`.github/workflows/slsa-build.yml` path currently fails under the org actions
policy (the upstream reusable generator's internal actions are tag-pinned, which
"pin to full-length SHA" rejects — see run 29387794215). A consolidation onto the
same `actions/attest-build-provenance` mechanism used for the container image is
staged for owner application; no source-tarball provenance claim is made until it
lands and verifies.
